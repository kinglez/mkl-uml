## Bounded state and change analysis

The quote goal is read-only, so no state-machine lifecycle, concurrency transaction or persistence protocol is necessary for this example. This is a scope judgment, not a claim those artifacts are never needed. Adding coupon redemption, stacking, catalog refresh or order creation would change this baseline and require affected-scope requirements/analysis/PDR review before implementation.

The negative-minimum acceptance/refusal policy remains outside this verified baseline. The implementation must not add a special sign rejection or a test that pretends to settle it. Integer representation and the ordinary comparison can exist without establishing a business acceptance policy for that excluded input.

## Message and language contract

DS-01 uses explicit synchronous calls and replies to the original caller. PriceQuote is constructed internally during completion and returned by value; it has no independently interacting lifeline in the maintained view. Its constructor invariant remains explicit in the completion note and MC-01. Replies and internal construction do not generate ordinary operations. No asynchronous Signal, callback or destruction behavior is in scope. Refusal on an exception reply propagates to the boundary and terminates the quote; it does not resume a success path.

All terminating break operands are at the outer quote-interaction level and cover all nine lifelines. The explicit full-span note uses actual first/last participants and introduces no call. Normalized historical illustrations of nested/narrow frames are preserved under `../review-history/` and were corrected following actual review. PlantUML 1.2026.7 crashed on `note across` inside these frames (exit 200); the equivalent explicit endpoint note renders successfully. The initial explicit creation message DS-01-M10 is retired from the message view, not reused; its internal construction responsibility is preserved by the completion note and RF-08/AD-01. Omitting a separate value-result lifeline is an abstraction choice, not early construction or a change in result behavior.

DS-02 is a separate technical test-harness interaction for RNF-02. It is not another user goal and does not claim coverage of any CU branch or analysis Controller. `sequence-scope.json` fixes these distinct scopes; DS-01 receives the full specification/robustness/domain checks, DS-02 receives domain/notation checks, and both feed operation provenance and CDR. The source per-file coverage checker cannot aggregate scoped sub-interactions automatically.

The Python reference implementation uses `datetime.datetime` with zero UTC offset, immutable dataclasses, `typing.Protocol`, `Mapping`, `Optional` and tuples. UML `void` maps to Python `None`; UML `String` to `str`, `DateTime` to aware `datetime`, `Map<K,V>` to `Mapping[K,V]`. Type annotations alone do not validate deliberately malformed input. Adapter/domain checks enforce the selected contracts; constructor/private helpers are implementation details except where their invariant is explicitly recorded.
